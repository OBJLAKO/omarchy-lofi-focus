# Live controls and persistent Solo — 2026-10-08

The follow-up fixes the reported jumping panel, release-only sliders and hard
to discover source isolation. It keeps the 3.5 stereo DSP, source library and
dependency graph unchanged. The prior [coverage review](3.5-COVERAGE-REVIEW.md)
and [resource measurements](PERFORMANCE-3.5.md) retain their exact older binary
identities; they are not new measurements of this follow-up executable.

## Cause and behavior

The panel assigned a new imported-sound array on every status, including an
unchanged empty array. Its derived sound-option array then replaced the sound
card Repeater model, destroying cards, expanded controls and the active mouse
grab. Stable catalog data now stays in place while changing audio values update
the existing controls. The installed controller PID and shell logs supported
delegate reconstruction rather than a daemon or plugin-file reload per edit.
The first edit also made the scene's dirty caption appear above the grabbed
control, shifting its position. That caption now occupies one permanent line.

The old controls connected only the slider's release signal. The shared control
now paces intermediate edits at 60 ms, flushes the final value immediately and
retains the local gesture value across delayed status echoes. Seeking uses
120 ms pacing. Disconnected numeric edits coalesce by parameter; ordinary
transport, scene and source actions retain their order.
Latest-value guards expire after 1.5 seconds and replay the most recent
authoritative status with a one-shot timer, including when stopped. A failed
numeric action clears only its own matching value; an older failure cannot
clear a newer value. Status updates never emit slider edit commands. No timer
polls the stopped controller continuously.

Every card exposes Solo, including collapsed cards, and Mix names the isolated
sound with a Back to mix action. `audition <id> hold` has no timer and is
runtime-only. The old `on` command retains its eight-second preview for
compatibility. Pause/stop, transport, scene application, selected-source failure
or removal and actual external preference changes still end isolation. Changing
the selected card or a slider does not. Solo requires an active playing layer;
it does not start stopped audio or change other saved gains/enabled flags.

Successful settings commands now normalize to the same form used by the
preference reader before applying/saving. Previously `vol` wrote an integer
while a watcher reread it as a float; unequal JSON representations triggered a
false external-change reload and cancelled Solo. A new regression reproduced
the failure immediately after `vol noise-rain 49`, then passed after this fix.
No deferred persistence, new runtime thread, DSP buffer, dependency, remote
service or downloaded data was introduced.
