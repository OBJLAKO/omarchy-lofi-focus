# Skylofi 3.5 security and publication review

Review date: 2026-10-07. Scope: the local 3.5 implementation, expanded offline
audio, personal imports, native decoder/mixer, scene input, existing network playback, manifest
and official marketplace requirements. The records below describe work
actually run or source actually read; they do not claim marketplace approval.
The final local preview executable was packaged and checked against this
working tree. The reports cover selected local file hashes; they are not an
exact published-commit marketplace check. [bin/BUILD-IDENTITY.json](../bin/BUILD-IDENTITY.json)
records the committed sources and final local executable. It describes a
locally built preview, not a CI-built or marketplace-approved artifact.
No release or marketplace publication was performed.

## Source boundaries reviewed

| Boundary | Observed controls |
| --- | --- |
| Offline assets | Catalog IDs identify bundled files. The new native path canonicalizes the selected file and confines bundled sound paths to `assets`, and imported sound paths to the private state `sounds` directory. The decoder reads files directly, without invoking a shell, FFmpeg or a network downloader. |
| Personal imports | Explicit absolute local paths only; supported extensions, regular files, bounded reads and a private atomic copy. The source opens with `O_NOFOLLOW` and `O_NONBLOCK`; its opened descriptor must still be a regular file within the size limit, closing a stat/open race involving symlinks or FIFOs. Safe generated filenames and catalog validation reject traversal. Personal storage is bounded to 24 files, 64 MiB per file and 512 MiB total, checked again against actual read bytes. Probe and initial-packet validation precede metadata registration; failed copies are removed, and removal targets the private copy. |
| Decoder and output | A single local output has 16 source slots and two shared effect buses. Decoder workers use fixed 16,384-frame queues; allowed rates are 8–192 kHz, and accepted converted packets are mono/stereo and capped at 65,536 frames. Empty-packet traversal is bounded. These limits do not claim to bound all internal codec allocations. Decoding and file access occur away from the renderer. Worker handles cancel and join on removal/stop. |
| Room parameters and lifetime | Finite values are clamped before DSP; distance, width, pan, softness, sends and master gain are bounded. Reverb feedback stays below unity, echo feedback is fixed below unity, and a final peak/nonfinite guard limits output. Pause silences wet tails. Clearing the stopped/empty local mix cancels and joins every decoder; the controller keeps one silent output for a 600 ms idle grace, allowing quick restart to reuse it, then drops the output. CPAL release completes asynchronously; measured lifetime scope is in the performance report. |
| Scenes | IDs and source references are validated against the catalog. Scene names are bounded; saved scenes are capped at 32 and simultaneous local layers at 16. Scene restoration excludes device master settings and validates missing sources before playback. |
| Existing subprocess playback | mpv/yt-dlp receive argument arrays, with `--` before media; user mpv scripts/configuration are disabled. YouTube links remain canonical HTTPS video URLs on explicit supported hosts. Extractor output, IPC frames, command arguments and client counts are bounded. |
| Network sources | RSS accepts HTTPS feeds, redirects and enclosures, rejects DTDs, caps data at 8 MiB, enclosure attributes at 64 and playlists at 12 enclosures. It uses quick-xml 0.41.0, covering the duplicate-attribute CPU and namespace-allocation fixes; its plain `Reader` does not use namespace resolution. Radio still includes explicitly cataloged HTTP ATC streams; the 3.5 local library adds no remote audio URLs. |
| State and local IPC | Runtime/state directories must be owned directories with mode 0700. Socket/log files use private permissions; atomic settings writes use exclusive temporary files. The controller socket is local. Existing process cancellation pins identities through pidfds. |
| Maintenance tooling | Audio generation and dependency-notice collection are explicit development steps. The installed launcher never downloads, compiles or installs code. New sound files carry original CC0 provenance; pre-existing CC BY credits remain intact. |

The native local path and scene code were reviewed while being implemented.
Unit and integration results are listed above; no sanitizer or hardware
listening result is inferred from this source review.
Catalog customization and executable search paths remain trusted user inputs.
Network codec/provider behavior remains the responsibility of the installed
mpv/yt-dlp stack; diagnostic logs can contain source URLs.

## Remaining release checks

1. Complete hardware listening/UI review and freeze the implementation
   selected for release. Rerun affected checks if that review causes another
   code change; a local manifest pass alone is
   insufficient for the new output, decoder and scene lifecycle.
2. Retain the local source/binary build identity with its matching executable;
   the packaged executable and checksum have already been checked.
   If the lockfile changes again, rerun the advisory comparison and
   regenerate dependency notices. Kira, CPAL,
   ALSA, rtrb and Symphonia add dependencies; recheck `readelf` on the final
   ELF rather than carrying forward the old 3.0 dynamic-library list. Ubuntu
   build CI includes the ALSA development package for the new CPAL backend.
3. Rerun affected local checks if any selected runtime file or the binary changes
   after this final-preview report. An exact release commit still needs the
   marketplace's own commit-bound validation and review.
4. After the user's release approval, the existing `sky.lofi` marketplace
   update must name the exact 40-character upstream commit. The marketplace
   performs its own check and an authorized maintainer reviews the bundled
   executable capability. No marketplace request or publication was made as
   part of this review.

The official [security policy](https://github.com/omacom/omarchy-plugin-marketplace/blob/c82981ef2a52599c3a5545848a3589243ea636fc/SECURITY.md)
classifies executable binaries as requiring maintainer review. The official
[verification workflow](https://github.com/omacom/omarchy-plugin-marketplace/blob/c82981ef2a52599c3a5545848a3589243ea636fc/VERIFICATION.md)
binds checks and approval to one exact commit; later upstream changes are not
covered by an earlier snapshot. Local tests, tags and checksum files do not
confer marketplace verification.
